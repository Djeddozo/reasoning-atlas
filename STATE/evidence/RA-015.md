## Built in this slice
- `services/atlas/continuity.py` and `scripts/resume.py`:
  - `claim` writes the claim (task, owner, session, branch) to STATE/active-task.json.
  - `checkpoint --next "…"` stamps the exact next action. The checkpoint is the last commit that changed STATE/active-task.json, so it never has to name its own commit.
  - `show` rebuilds the stop point from the repository alone: the claim, the checkpoint commit, commits after it, uncommitted files, the next action (from the claim or the evidence file's "Exact next action"), and numbered first steps. `at-checkpoint` means nothing is at risk; `before-checkpoint` means work after the checkpoint must be inspected.
  - `effect begin KEY` / `effect finish KEY done|failed|not_done`: a write-ahead ledger in STATE/effects.json. The intent is written (atomically) before an external effect, the outcome after it. On a repeat, `begin` returns `skip` (exit 3) for done effects and `verify` (exit 4) for effects whose outcome is unknown, so a guarded command (`begin && git push && finish`) never runs twice.
- The handoff packet (Forge › Build › Continue building) now includes this resume state and tells the next session to run `python scripts/resume.py show` first and to wrap external effects.
- Module manifest: `atlas.progress.resume` (status tested, this file as evidence).

## Validation: controlled stops
Each "session" is a new process that sees only the repository. The external effect appends a line to a file outside the repository, so a duplicate would show as a second line.

Automated (`tests/test_continuity.py`, 8 tests):
- Stop before the checkpoint with a push in flight (effect done, outcome not recorded, nothing committed): the fresh session reports `before-checkpoint`, the uncommitted file, the previous next action, and "verify push" as its first step. Retrying the push step returns `verify`; the remote still has one line. After `finish … done`, a further retry returns `skip`.
- Stop after `begin` but before the effect: `verify`, then `finish not_done`, then the effect runs once (attempts 2, remote one line).
- Stop after the checkpoint (switch from Codex to Claude): `at-checkpoint`, nothing uncommitted, the new next action, "do not repeat push"; retry returns `skip`.
- Commits after the checkpoint without a stamp are reported as unstamped work; next action falls back to the evidence file; a done task points to the next ready task; bad input is refused.
- The handoff packet carries the resume state.

## Not run / limitations
- Not yet shown: a live Claude or Codex session resuming an interrupted RA task from the packet alone. The drill replaces the agent with scripted processes. This session itself started from the repository only, but it did not resume an interrupted task.
- Uncommitted work and an unsettled effect intent survive only in the same folder. A session on another computer sees only pushed commits; there, effects must be naturally idempotent (git push of the same branch, one pull request per branch) or checked on the remote. The ledger makes that check explicit; it does not make an unpushed intent visible elsewhere.
- Agents must use the wrapper; effects done without `effect begin` are not protected.
